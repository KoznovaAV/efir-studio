# Детальный обзор и исходный код

Проверено 23 ноября 2026 года. Ссылки на коммиты фиксируют прочитанный снимок. Наличие CI означает наличие конфигурации в репозитории. Фактические прогоны конкурентов в этой сессии не проводились.

## Velorn

Наиболее близкий заменитель на Windows. В README отдельно документированы монтаж, субтитры, экспорт и редакторские MCP-команды без ComfyUI. Генерация подключается локальным графом, Comfy Router либо внешним GPU. История проектов, прокси, эффекты и экспорт опережают объём первого EFIR. Отдельно стоит проверить перенос проекта вместе с медиа и изменение одной сцены через повторный экспорт. Кодовая лицензия GPL-3.0 приемлема для собственного GPL-форка. Он потребует сопровождения интерфейса, updater, агентских поверхностей, политик и ComfyUI-интеграций. Функции локального CPU-монтажа сравниваются напрямую. [README фиксированного снимка](https://github.com/VelornLabs/velorn/blob/387170309acc4146d883d9f31b140fb35fc5c4ad/README.md), [манифест](https://github.com/VelornLabs/velorn/blob/387170309acc4146d883d9f31b140fb35fc5c4ad/package.json), [релизы](https://github.com/VelornLabs/velorn/releases).

## Nomi

Наиболее убедительный общий кандидат. Есть проекты, references, раскадровка, генерация, редактор и управление из внешних агентов через MCP. В версии v0.24.1 Electron entry point управляет RPC и локальным MCP HTTP и содержит привязку профиля к идентичности Electron для safeStorage. Windows gate явно запускает E2E и полноценные пользовательские journeys. AGPL-3.0 позволяет форк с сохранением соответствующих обязательств. Цена поддержки включает Electron, desktop/core RPC, модельные каталоги, агента и UI. Не установлено, какой процент проектов переносим без ручного восстановления путей и что повторная сборка экономит на ноутбуке. [Релиз](https://github.com/aqm857886159/Nomi/releases/tag/v0.24.1), [Electron](https://github.com/aqm857886159/Nomi/blob/15ca8672bc8607c7c4ca537559540c77cb775750/electron/main.ts), [Windows CI](https://github.com/aqm857886159/Nomi/blob/15ca8672bc8607c7c4ca537559540c77cb775750/.github/workflows/win-gate.yml).

## IV Studio

Ближайшая основа для разрешительного форка. MIT, Windows Portable, повторяющиеся персонажи, голос, мастер короткого фильма, редактор, ComfyUI и MCP. Манифест подтверждает Electron/Vite, отдельное Windows portable packaging и dependency на статический FFmpeg/ffprobe. Возможности отдельных моделей нужно считать отдельно от интерфейса редактора. Установка, выборочно затрагиваемые участки кэша, восстановление очереди, секреты и русская речь требуют отдельного прогона или чтения профильных модулей. Для CPU-сборки полный форк приносит значительно больше зависимостей, чем прямой запуск FFmpeg. [README фиксированного снимка](https://github.com/hollisorg/iv-studio/blob/1d04de2b1d0877758bcc263c87bb15daed521519/README.md), [манифест](https://github.com/hollisorg/iv-studio/blob/1d04de2b1d0877758bcc263c87bb15daed521519/package.json).

## Qamba Studio OSS

Прямой прецедент повторного использования клипов. Python worker описывает нормализацию и кэш клипа по хешу операций. Rust-модуль поднимает временный loopback PostgREST-совместимый прокси для Python и маршрутизирует запросы к единственному writer локального JSON из webview. Доступ к прокси по случайному токену на прогон. README описывает одну дорожку durable jobs. CI задаёт Python-тесты с FFmpeg. Это зрелая схема для большего продукта и непропорционально сложная для первой настольной сборки. Windows E2E, хранение облачных ключей и результаты 6 ГБ остаются открытыми. [Сохранение и прокси](https://github.com/qamba-labs/qamba-studio-oss/blob/c16a704cffd3a3790c5dc70e67b99bd388c8c552/src-tauri/src/dbproxy.rs), [рендер](https://github.com/qamba-labs/qamba-studio-oss/blob/c16a704cffd3a3790c5dc70e67b99bd388c8c552/worker/handlers/render.py), [CI](https://github.com/qamba-labs/qamba-studio-oss/blob/c16a704cffd3a3790c5dc70e67b99bd388c8c552/.github/workflows/ci.yml).

## OpenField

MIT подтверждена текстом LICENSE. Дизайн особенно хорошо показывает, как секция Director превращает постановочные решения в граф и как результат можно привязать к точному workflow JSON. Local ComfyUI, обратная связь по шагам и отмена задокументированы. Авторы указывают 24 ГБ VRAM для видео и измерения на RTX 5090 с 32 ГБ. Для пакета сцен и одного небольшого клипа на RTX 4050 в сочетании с 16 ГБ RAM воспроизводимого результата не найдено. [README фиксированного снимка](https://github.com/wexloops/openfield/blob/1c364121cd299da3959d7c8e77e12e9295a37943/README.md), [LICENSE](https://github.com/wexloops/openfield/blob/1c364121cd299da3959d7c8e77e12e9295a37943/LICENSE).

## ComfyUI

Сильнейший кандидат на внешний движок. Запуск на Windows документирован. Сервер создаёт PromptQueue, исполнитель содержит кэш узлов и варианты под давлением RAM. Это механизм вычисления графа, а целостность сцены, история редакторских правок и финальный монтаж остаются над ним. Выбранный вариант интеграции в следующем этапе — ограниченный адаптер к документированным маршрутам и пользовательским графам API. Сторонние Python nodes и версия весов имеют собственные риски и сроки обновления. Импорт готового материала остаётся базовым путём. [Релиз v0.46.0](https://github.com/Comfy-Org/ComfyUI/releases/tag/v0.46.0), [сервер](https://github.com/Comfy-Org/ComfyUI/blob/f08f28aaac5447af3b2e8a83e2f53c8774d23151/server.py), [исполнитель](https://github.com/Comfy-Org/ComfyUI/blob/f08f28aaac5447af3b2e8a83e2f53c8774d23151/execution.py), [Windows](https://docs.comfy.org/installation/comfyui_portable_windows).

## Kdenlive

Технический базис сравнения для CPU-этапа. Qt и KDE над MLT/FFmpeg дают многодорожечную нарезку, прокси, субтитры, звук и экспорт. Это первый кандидат на полноценный монтаж вручную. Интероперабельность через OpenTimelineIO стоит проверять на конкретной сборке, включая пути, субтитры и скорость. Слабое место для данного сценария — повторяемое соединение материала шота, его параметров и автоматических сценарных правок. Реальная стоимость ручного процесса ещё не измерена. [Архитектура и лицензия](https://kdenlive.org/about/), [документация прокси](https://docs.kdenlive.org/en/getting_started/configure_kdenlive/configuration_proxy_clips.html), [репозиторий OTIO-адаптера](https://github.com/KDE/kdenlive-opentimelineio).

Ширина команды, SLA upstream и лицензионный статус всех transitive dependencies не измерены. Для решения о форке нужно отдельно изучить историю CODEOWNERS, авторов релизов и восстановление после смены версии внешнего worker.
