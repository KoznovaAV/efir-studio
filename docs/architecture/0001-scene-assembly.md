# ADR 0001. Независимая сборка сцен поверх FFmpeg

Дата решения: 23 ноября 2026 года. Статус: принято для первой версии.

## Контекст

[Исследование рынка](../market-research/README.md) обнаружило несколько студий, уже совмещающих ComfyUI, раскадровку, агентов и многодорожечный монтаж. Документированный минимум для локальной генерации LTX Desktop на Windows превышает доступные 6 ГБ VRAM. У FramePack заявлен порог 6 ГБ, но время и память под Windows на целевом ноутбуке требуют измерения. Для первой версии нужен рабочий путь от материалов к ролику на CPU.

## Решение

COMPOSE с узким стартовым сценарием. EFIR хранит сцены, переносимые копии исходников, происхождение материалов и параметры монтажа. Готовые клипы можно брать из генеративных инструментов, камеры и редакторов. FFmpeg выполняет техническую сборку. Kdenlive и Velorn остаются кандидатами для монтажа и генерации. Python и Tk дают общее ядро для CLI и простого локального интерфейса. Сервер, зависимости из PyPI и модели для штатной работы не требуются.

Проект — каталог с версионированным JSON и файлами, адресованными SHA-256. Сцену задают клип или изображение, длительность, начальная позиция клипа, contain/cover, дорожка исходного звука, отдельный голос и субтитр. В первой версии частота 25 кадров/с. Целое число кадров задаёт общую шкалу. Субтитры и звук используют эту же шкалу.

Ключ кэша сцены включает исходники, параметры кодирования и версию FFmpeg. Названия, порядок и субтитры исключены из ключа. При правке меняются только затронутые сегменты, а MP4 собирается заново. В сегментах H.264 и PCM. Выход использует H.264 без повторного кодирования видео и один непрерывный AAC-поток. Поддерживаются встраиваемые субтитры и отдельный SRT. Проект, сегменты и MP4 пишутся через временные файлы в той же файловой системе. Изменения из двух открытых окон обнаруживаются сравнением версии файла под локальной блокировкой.

FFmpeg вызывается без оболочки. Для медиа используются локальный протокол, явные форматы и адреса внутри проекта. Приложение не отправляет материалы наружу. Копии исходников и кэш занимают диск. Предусмотрены повторный запуск и очистка кэша вручную при закрытом приложении.

## Границы и проверка решения

Проверка v0.1: три сцены, включая движущийся клип и голос, кириллица, экспорт 9:16, повторное открытие и правка одной сцены с наблюдаемым попаданием в кэш остальных. Пилот и сравнение с Velorn и Kdenlive следуют по [протоколу](../market-research/BENCHMARK_PLAN.md). Расширение продукта зависит от заметной экономии времени на правках и переносе проекта. Если конкуренты дают сопоставимый рабочий процесс на этой машине, EFIR можно оставить как узкую утилиту сборки.
