# Архитектурное решение EFIR Studio

23 ноября 2026 года. Принято решение **D** по обозначениям задания. EFIR продолжает развиваться как независимый локальный оркестратор сцен с интерфейсом естественного языка. FFmpeg выполняет быстрый экспорт, Kdenlive остаётся внешним редактором, Ollama, движок русского TTS и ComfyUI подключаются отдельными адаптерами. Это уточняет COMPOSE из [ADR v0.1](0001-scene-assembly.md) и терминологию [первичного исследования](../market-research/STRATEGIC_OPTIONS.md), где буквы означали другие варианты.

**Почему D.** Velorn, Nomi и IV Studio уже покрывают существенную часть редактора и управления генерацией. Qamba реализует кэш клипов и устойчивую очередь. Kdenlive уже решает многодорожечный монтаж. Основание продолжать собственный код EFIR состоит в переносимом сценарном проекте, естественно-языковых правках с просмотром изменений и управлении несколькими движками с разными требованиями. Рыночная ценность этой связки пока гипотеза. [Проверка исходников](../research/COMPETITOR_VALIDATION.md), [практический прогон](../research/PRACTICAL_COMPARISON.md).

**Что меняет решение.** Если Velorn через документированный MCP выполняет тот же цикл без потерь при переносе и с сопоставимыми трудозатратами, стратегия C становится предпочтительной для этого сценария. До расширения v0.3 сравнить живые сессии минимум двух операторов на одинаковом наборе и одном пилоте. Порог для отдельного продукта — не менее 25% выигрыша по медиане времени на серию правок и перенос либо воспроизводимый командный сценарий, отсутствующий в исследованных хостах. Если преимущества нет, оставить сопровождение CPU-утилиты или вынести нужный адаптер upstream.

**Разрешение на следующий этап.** Закрыть P0 из аудита, затем проверить один русский CPU-голос и одну небольшую локальную LLM на целевой машине. Публичный FFmpeg-процесс и файловый формат v0.1 остаются входом для миграции. Поставка GPU-весов и собственный многодорожечный редактор не входят в согласованный объём.
