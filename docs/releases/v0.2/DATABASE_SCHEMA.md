# Формат проекта SQLite

`project.sqlite` использует `PRAGMA user_version` и миграции по порядку. Версии 1, 2 и 3 добавляют проект и ревизии, очередь и события, затем историю планов. Каждая миграция и пользовательская запись выполняются в транзакции. FK проверяются при каждом подключении.

| Таблица | Содержимое и связь |
|---|---|
| `project` | Уникальный ID и текущая ревизия `head` |
| `revision` | Неизменяемый JSON-снимок названия, формата, фона и всех сцен. ID родительской ревизии, причина и время |
| `job` | ID, ключ идемпотентности, тип, FK исходной ревизии, параметры, статус, попытка, аренда, срок, прогресс и результат |
| `job_event` | Переход состояния для задачи и время перехода |
| `proposal` | JSON-операции, исходная ревизия, пользовательский текст, имя модели, решение и связанные задачи |

SQLite — источник текущего состояния и истории. JSON-снимок внутри SQLite хранит сцены вместе, так что порядок, фон и текст фиксируются одним коммитом. Идентификаторы сцен сохраняются при правках, переносе и миграции.

Пути в снимках относительны. Медиа лежат в `assets/<sha256>.<ext>`. `exports/<job-id>.mp4` проверяется по хешу в завершённой записи задачи. `.cache` восстанавливается через FFmpeg. Запись из временного файла атомарно заменяет либо добавляет конечный файл. Если процесс завершится между публикацией файла и коммитом строки, задача подберёт его назначение при повторе. Копирование включает только записи зафиксированного SQLite-снимка и проверенные результаты.

Аренда задаётся на 15 секунд. Отмена активной задачи переходит через `cancel-requested`. Просроченная аренда позволяет повтор, максимум три попытки. Повтор завершившейся ошибкой задачи требует действия пользователя. Открытие перенесённой копии восстанавливает активные задачи при первом запуске рабочего процесса.
