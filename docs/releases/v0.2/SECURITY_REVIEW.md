# Проверка безопасности AI-профиля

## Получение компонентов

- Манифест GitHub Releases и опубликованный sha256sum.txt совпали для официального архива Ollama 0.40.19. SHA-256 архива — 0114b9f103d783b96f14390cf7f11d0fa360040b3ee9941f370fdee503cca308. При выборе проверялись опубликованные advisories Ollama и официальный стабильный релиз. [Advisories](https://github.com/ollama/ollama/security/advisories), [релиз](https://github.com/ollama/ollama/releases/tag/v0.40.19).
- Версия 0.40.19 новее версии 0.35.0, в которой исправлена CVE-2026-103663 по данным CERT Polska. [Уведомление CERT Polska](https://cert.pl/posts/2026/10/CVE-2026-103663/).
- SHA-256 слоя GGUF — 3e4cb14174460404e7a233e531675303b2fbf7749c02f91864fe311ab6344e4f. Перед установкой проверяется digest манифеста и после установки — Q4_K_M через loopback API.
- Голос закреплён на Git-ревизии Hugging Face. Локальные ONNX, JSON и карточка проверены независимо через SHA-256. Установка Piper использует wheel с хешем PyPI, список версий зависимостей находится в scripts/piper-win-py313.lock.

## Границы выполнения

Сервер запускается с привязкой к loopback и OLLAMA_NO_CLOUD=1. Лаунчер проверяет реальный слушающий интерфейс и идентифицирует собственный процесс по пути и времени запуска. В журнале Ollama подтверждены Ollama cloud disabled: true и Listening on 127.0.0.1:11434. Приложение ходит по прямому HTTP-соединению к 127.0.0.1. Запросы содержат пользовательский текст и ограниченный набор полей сцен. Пути, содержимое медиа и произвольные инструменты модели отсутствуют в контракте.

Типы операций, поля, идентификаторы и ожидаемая ревизия проверяются отдельно от ответа движка. Применение плана требует подтверждения. Ollama не получает управление оболочкой. Piper работает отдельным процессом с конкретным проверенным голосом и стандартным вводом. Закрепление бинарников и loopback ограничивают поверхность, а локальный процесс может обращаться к порту без аутентификации. Закрывайте собственный сервер после использования.

Установка не назначает службу, не меняет брандмауэр и не добавляет задачи автозапуска. В 30 срезах процессов Ollama во время реальной генерации наблюдалось ноль TCP-соединений за пределами loopback. Основной прогон выполнен с недоступным HTTP-прокси и сохранённым loopback. Это наблюдение процессов, а не захват каждого пакета. Проверка с отключённым сетевым интерфейсом остаётся открытой.
