23 ноября 2026 года. Проверен [PR №1](https://github.com/KoznovaAV/efir-studio/pull/1), head `bdd111befdfb3c64819a8101f2f0ff4360a1d143`, base `bb5fb410a21d4b1bad0600acc8bc18fbe6970a6c`. На момент проверки PR открыт и не слит. Рабочая ветка до начала аудита совпадала с опубликованным head и была чистой. Исправления подготовлены в `codex/efir-v01-audit` поверх head PR №1. [GitHub Actions](https://github.com/KoznovaAV/efir-studio/actions/runs/45184012248).

**Вердикт.** v0.1 — компактный прототип автономной сборки сцен. Границы `project.py`, `render.py`, CLI и Tk подходят текущему объёму. MIT, хешированные исходники, атомарная запись результата, CPU-режим и точечное перекодирование полезны для монтажного слоя. Концепцию AI-студии v0.1 покрывает в части импорта, сцен, грубых субтитров и экспорта. Чат, сценарный конвейер, персонажи, генерация и управление ресурсами остаются за пределами этой версии. [Тесты](TEST_REPORT.md), [долг](TECHNICAL_DEBT.md).

| Область | Наблюдение и решение |
|---|---|
| Повреждённый кэш | **P1, исправлено.** Любой ненулевой MKV считался попаданием. При обрезке сегмента до 2048 байт экспорт вернул `reused=1`. Теперь путь включает ключ и SHA-256 содержимого. Сегмент с несовпавшим хешем пересобирается, новый публикуется атомарно. `-xerror` переводит ошибки FFmpeg в отказ. Формат проекта прежний. Старый кэш будет перестроен при первом запуске. |
| Временная шкала | **P1, исправлено.** Для звука, начинающегося на 0,40 с позже видео, при trim на 0,08 с звук слышен до ожидаемых 0,32 с. Причина — сброс PTS до компенсации. Ресемплер теперь компенсирует начальный сдвиг по PTS, затем поток приводится к точному числу PCM-сэмплов. |
| Снимок сцен | **P1, исправлено.** При изменении объекта проекта между кодированием и упаковкой MP4 мог содержать видео старой сцены и субтитры новой. Тест на стадии склейки изменил длительность с 10 до 12 кадров и текст. Экспорт теперь использует один снимок сцен. |
| Пропорции кадра | **P1, исправлено.** Прежнее масштабирование сначала вписывало размеры хранения, затем назначало квадратные пиксели. Для тестового источника 100×100 с SAR 2:1 белая область занимала 540×540 вместо 540×270. Размеры для contain и cover теперь рассчитываются по пропорциям отображения перед нормализацией SAR. |
| `.cache/scenes.ffconcat` | Конфликт общего файла не воспроизвёлся и отсутствует в прочитанном коде. Имена `scenes.ffconcat` и `captions.srt` передаются в `staged_file` как образцы суффикса. Фактические файлы `.efir-*.ffconcat` и `.efir-*.srt` уникальны. Два экспорта одного каталога достигли барьера перед склейкой и получили собственные порядок кадров и субтитры. |
| Одновременные экспорты | Разные MP4 из одного проекта работают независимо. При параллельном холодном экспорте ключ может кодироваться дважды. Публикация сегментов по SHA разделяет результаты, при совпадении байтов используется существующий файл. Без `--overwrite` одно назначение получает одну публикацию. При двух разрешённых перезаписях более поздняя публикация может заменить более раннюю. |
| MP4, звук и субтитры | H.264 в сегментах копируется в MP4, PCM объединяется в AAC, мягкие субтитры и SRT используют шаг 40 мс. Для 96 секунд проверены 2400 кадров, 25 fps, AAC 48 кГц и `mov_text`. Несколько реплик, VFR и реальная запись требуют расширения матрицы. |
| Перенос и ревизии | `project.json` v1, относительные имена assets, проверка SHA-256, атомарная запись и отказ при устаревшей ревизии. Есть тест копии и длинный прогон из каталога с кириллицей и пробелами. Сетевые файловые системы не проверены. |
| Отмена и сбой | Отмена завершает дочерний FFmpeg. Временные файлы очищаются, прежний MP4 сохраняется. Новый тест отменяет после реального запуска FFmpeg. Готовые сегменты доступны при повторе. Аварийное завершение может оставить staging, долговременного восстановления очереди нет. |
| Пути и внешние медиа | Вызов FFmpeg массивом аргументов без shell, протокол `file`, заданные демультиплексоры для источников, отключённые внешние ссылки MOV/MP4 и безопасный concat. Имя медиа соответствует хешу и допустимому расширению. Проверка путей снижает риск выхода из проекта. Отдельная изоляция декодера и обмен с одновременно подменяющим файлы процессом остаются непроверенными. |
| Ошибки и сопровождение | Ошибка входа или FFmpeg содержит стадию и хвост stderr. Тесты охватывают существующие CLI и Tk. Угловые случаи UX, Windows-путей и редких форматов требуют интеграционных тестов. Процент покрытия не измерен. |
