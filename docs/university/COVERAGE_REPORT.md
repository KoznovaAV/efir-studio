Учитываются все производственные Python-модули в `efir/`, включая Tk. `patch = subprocess` измеряет дочерний CLI. `coverage combine` объединяет процессы перед генерацией отчётов. Исключения из production-замера не добавлены. В ОС различаются системные ветви открытия файла и блокировки. Проверка симлинка выполняется там, где среда разрешает его создание. FFmpeg как внешний бинарник проверяется декодированием результата и кодами завершения, а знаменатель покрытия состоит из Python-строк EFIR.

В стандартном выводе Coverage.py таблица `Cover` при включённых ветвях объединяет строки и ветви. Итоговый скрипт дополнительно печатает оба показателя отдельно. CI сравнивает точные числа исполняемых строк, без округления до 95%. При недостаточном покрытии создаются отчёты и возвращается код 1.

```powershell
python -m pip install -r requirements-qa.txt
$env:EFIR_TEST_DESKTOP = '1'
$env:EFIR_FFMPEG = (Resolve-Path .efir-local/ffmpeg.exe).Path
$env:PYTHONUTF8 = '1'
python -m coverage erase
python -m coverage run -m unittest discover -s tests -v
python scripts/coverage_report.py
```

Артефакты появляются в `reports/qa/`. `coverage.txt` содержит терминальный отчёт, `html/index.html` открывает отчёт по строкам, `coverage.xml` — Cobertura, `coverage.json` — точные числители, знаменатели и пропущенные ветви. GitHub Actions прикрепляет архивы по ОС, GitLab настроен публиковать те же данные. [Coverage.py и процессы](https://coverage.readthedocs.io/en/7.13.5/subprocess.html)
