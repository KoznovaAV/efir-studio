# Как работает E2E-тест

`CliEndToEnd.setUp` создаёт изолированный каталог. `assets` вызывает настоящий FFmpeg для генерации воспроизводимых медиа. `cli` запускает публичный интерфейс EFIR через `sys.executable -X utf8 -m efir`. Каждый вызов стартует заново, поэтому тест проверяет сохранение проекта между процессами. `execute` ограничивает время вызова, собирает stdout и stderr. При отказе assertion показывает диагностический вывод.

`test_create_export_modify_and_reuse_scenes` хранит ID второй сцены из stdout команды `add`. После импорта внешние тестовые файлы удаляются. Экспорт поэтому зависит от реального копирования и поиска медиа по хешам. `edit` меняет только длительность целевой сцены. По счётчикам stdout тест отличает попадания в кэш от повторного кодирования.

| Проверка | Что ловит |
|---|---|
| Код возврата 0 и размер MP4 больше 1000 байт | Наличие завершённого вызова и нетривиального файла. Сами по себе эти признаки ещё не доказывают корректное видео |
| `540x960`, временная база `1/25`, PTS от 0 до 29 или 26 | Неверный профиль, пропуск кадра, смещение начала и неправильную длительность |
| Несколько разных CRC в видеофрагменте | Подстановку неподвижного кадра вместо движущегося клипа |
| Декодирование аудио и сравнение числа семплов с кадровой шкалой | Отсутствующую дорожку или заметное расхождение длительности. Допуск 1024 семпла учитывает последний блок AAC |
| Порог амплитуды в начале и во второй сцене | Ошибку положения озвучки и подстановку пустого звука |
| Извлечение `0:s:0` и UTF-8-сравнение текстов и границ | Ошибки кодировки, отсутствующую дорожку и устаревший интервал после правки |
| `3/0` до и `1/2` после | Ненужное кодирование неизменённых сцен и потерю управляемого ключа кэша |

**Unit** проверяет отдельный контракт, например округление секунд до кадров. **Integration** проверяет взаимодействие компонентов, например восстановление повреждённого кэша или блокировку двумя процессами. **E2E** запускает всю цепочку через публичные команды и валидирует конечный результат внешним декодером. Отдельный Tk smoke вызывает реальные виджеты и фоновый рендер. Автотесты Tk подставляют ответы системных диалогов, а ручной сценарий проверяет сами окна.
