# Нагрузочное тестирование EFIR Studio

Эксперимент отделён от [сравнения с редакторами](../research/PRACTICAL_COMPARISON.md). Измеряется выполнение CLI, CPU-рендер и файловый кэш. Данные создаёт FFmpeg, проекты собирают публичные команды EFIR. Нагрузка ограничена 30 сценами, двумя экспортами одновременно, черновым разрешением 540×960 при 25 fps и тайм-аутом 120 секунд на отдельный замер.

## Методика

```powershell
python -m pip install -r requirements-qa.txt
$env:EFIR_FFMPEG = (Resolve-Path .efir-local/ffmpeg.exe).Path
$env:PYTHONUTF8 = '1'
python scripts/load_test.py --soak-seconds 60
```

Стенд сравнивает холодный и тёплый экспорт для 6, 18 и 30 сцен. Длительность растёт отдельно от числа шотов. В длинном проекте стенд ещё около минуты повторяет экспорт с прогретым кэшем. В параллельном кейсе два дочерних CLI используют новый общий кэш, но пишут в разные файлы. Стенд проверяет коды выхода, число кадров в каждом MP4 и счётчики сцен. Одновременная публикация в один MP4 остаётся отдельным контрактом будущей очереди.

`psutil` каждые 50 мс оценивает сумму RSS каждого дерева CLI и FFmpeg. RSS включает возможные общие страницы. Сумма последних наблюдавшихся `user + system` по процессам даёт нижнюю оценку CPU-секунд. Показатель процента мощности хоста делит их на стеночное время и число логических CPU. Пропуски короткоживущих процессов и фоновые задачи уменьшают точность. Время измеряется от запуска CLI до выхода, проверка файлов исключена из таймера. Пики RAM системы целиком, GPU/VRAM, температуры и бесконечная работа не измерялись.

## Найденная регрессия

Первый параллельный холодный прогон отказал с сообщением о выходе за границы проекта. В повторе зафиксировано, что Windows вернула тот же физический путь с префиксом `\\?\`, а сравнение `Path.is_relative_to` ожидало обычный путь. Контроль нормализует эквивалентные формы дисков и UNC для сравнения после `resolve`. Операции с файлами сохраняют исходный путь. Выход через родительский каталог, внешний диск и перенаправление симлинком проверяются отдельно. Добавлен интеграционный тест двух независимых CLI-процессов с общим холодным кэшем.

## Результат после исправления

26 ноября 2026 года, Windows 11 Pro build 26300, Intel Core i5-12450H, 12 логических CPU, 16 122 MiB RAM, Python 3.13.16, FFmpeg 7.1 essentials, psutil 7.2.2. GPU-ускорение для этих экспортов выключено.

Все 22 сценария завершились и прошли проверку числа кадров. В длительной серии за 64,033 с выполнено 15 тёплых повторов. Медиана 1,172 с, диапазон 1,109–1,246 с, максимальный наблюдавшийся RSS 60,86 MiB. Все 30 сцен каждого повтора были взяты из кэша. Средняя оценка загрузки всей CPU-ёмкости для холодного длинного запуска — 18,81%, для пары параллельных экспортов — 25,72%.

При двух холодных экспортёрах суммарно закодировано 24 сегмента, 12 ключей получили по два кандидата. Оба MP4 корректны. Предотвращение дублирования работы на одном ключе относится к будущей очереди. Короткая серия подтверждает стабильность проверенного сценария. Она не измеряет многосуточную работу или использование больших медиа.
