# Подготовка к защите

1. Откройте [сводку покрытия](COVERAGE_REPORT.md). Покрытие строк — доля исполняемых строк, до которых дошли тесты. Покрытие ветвей — доля зарегистрированных переходов управления, например обоих исходов условия. Coverage.py измеряет Python-процессы и объединяет результаты CLI с основным тестовым процессом. 95% — порог выполнения кода. Тест с плохими проверками может выполнить строку и пропустить ошибку. Проверяйте также граничные случаи, входы и наблюдаемое состояние результата.
2. Запустите [EFIR-E2E-01](E2E_TEST_CASE.md). Unit сравнивает локальный результат функции. Integration проверяет согласованность двух или более компонентов. E2E обращается к публичному CLI и проверяет результат независимым декодированием. Покажите разницу между первой и второй сборкой по счётчикам, кадрам и субтитрам.
3. Для [ручных тестов](MANUAL_TEST_CASES.md) откройте настольное окно и переставьте сцены. Автотест выполняет закодированные сравнения повторяемо. Ручной тест позволяет оценить реальный системный диалог, визуальную читаемость и реакцию интерфейса. Факт выполнения каждого сценария отмечается отдельно.
4. В [отчёте нагрузки](LOAD_TEST_REPORT.md) сравните холодный и тёплый экспорт, затем два параллельных. Нагрузка получена несколькими локальными CLI-процессами. Пик памяти оценён выборками. HTTP здесь не участвует.
5. [Docker](DOCKER_REPORT.md). Образ — неизменяемый шаблон файлов и запуска. Контейнер — экземпляр образа с процессом и файловым слоем. Volume — хранилище Docker вне жизненного цикла контейнера. В этом проекте bind mount подключает существующий каталог на компьютере с тем же результатом сохранения данных. Compose описывает образ, запуск, права и подключение хранилища одной конфигурацией. Tk оставлен нативным для системных окон. CLI и CPU-экспорт выполняются и в Linux-контейнере.
6. [CI/CD](GITLAB_CICD_REPORT.md). CI автоматически проверяет изменения, CD готовит или публикует артефакт при выполнении условий. Pipeline — полный прогон. Stage — этап, job — выполняемое задание, runner — исполнитель, artifact — сохранённый файл запуска. EFIR проходит качество, три уровня тестов, покрытие и smoke образа. Публикация разрешена для защищённого релизного тега. На защите используйте фактический статус GitLab и журналы GitHub Actions.
