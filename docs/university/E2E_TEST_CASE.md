# EFIR-E2E-01. Сборка выпуска и перерасчёт одной сцены

**Цель.** Проверить путь от создания файлового проекта до пригодного к воспроизведению MP4 и точечного повторного экспорта.

**Описание.** Тест запускает отдельные процессы `python -m efir`. FFmpeg создаёт PNG 96×96, движущийся H.264-клип 128×96 при 25 кадрах/с и WAV с тоном 660 Гц. Два субтитра на русском. Каждый прогон работает в отдельном временном каталоге с кириллицей и пробелами.

**Предусловия.** Python 3.11+ и FFmpeg с libx264, AAC, фильтрами lavfi и декодированием MP4. Указать `EFIR_FFMPEG` для отдельного бинарника. Для теста нужны локальная файловая система и возможность запуска дочерних процессов. Графическая сессия, модели и сеть не требуются.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Создать три синтетических файла и проект «Ночной эфир» | Команды завершились с кодом 0 |
| 2 | Добавить титр 0,40 с, клип 0,60 с с обрезкой начала на 0,04 с и внешним WAV, затем финал 0,20 с | Получены идентификаторы сцен. У первых двух сцен есть русские субтитры |
| 3 | Удалить три временных исходника вне папки проекта | Экспорт использует копии из `assets/` |
| 4 | Экспортировать черновой MP4 | Три сцены закодированы, кэш пуст для первой сборки, файл больше 1000 байт |
| 5 | Декодировать видеоряд, звук и субтитры | 540×960, 30 кадров с непрерывными PTS, 1,20 с при 25 кадрах/с. В начале тишина, на второй сцене сигнал. Второй субтитр занимает 0,40–1,00 с |
| 6 | Изменить длительность второй сцены на 0,48 с и повторить экспорт | Одна сцена закодирована, две взяты из кэша. Контейнер MP4 изменился |
| 7 | Проверить новый MP4 и внешний SRT | 27 кадров, 1,08 с. Звук доступен, второй субтитр занимает 0,40–0,88 с и совпадает по интервалу с внешним файлом |

**Общий ожидаемый результат.** Оба экспорта корректны, повторный экспорт сохраняет две сцены и обновляет длительность выпуска, звуковую дорожку и субтитры.

**Фактический результат.** 26 ноября 2026 года CLI-тест выполнен на Windows с FFmpeg 7.1. Получены 30 и 27 кадров, русские субтитры декодированы, кэш дал два попадания после правки. Проверки покрывают сигнал тонального WAV. Подробности среды и проверок Linux приведены в [сводке тестирования](TESTING_REPORT.md).

