# Отчёт об автоматизированном тестировании

Проверки продолжают [аудит v0.1](../audit/TEST_REPORT.md). Framework — `unittest`. XMLRunner используется только для вывода JUnit в CI. Код рендера запускает настоящий FFmpeg. В Tk проверяются состояния виджетов, сохранение, диагностика, очередь фонового экспорта, отмена и восстановление элементов управления.

| Набор | Что проверяется |
|---|---|
| `test_project.py`, `test_core_edges.py` | Валидация схемы, метаданные, перенос, дедупликация, выход за границы проекта, конфликт ревизии, межпроцессная блокировка, повреждённые данные, отказ FFmpeg, конкурентная публикация сегмента. |
| `test_render.py` | Реальный CPU-экспорт, SAR, задержка аудио, снимок сцен, точечная пересборка, параллельная сборка, восстановление сегмента и отмена после запуска FFmpeg. |
| `test_entry_points.py`, `test_desktop.py` | CLI-команды, реальные Tk-виджеты, smoke с фоновым FFmpeg, ошибки в диалогах и статус рендера. Диалоговые ответы в автотестах задаются программно. |
| `test_cli_e2e.py` | Файловый проект с импортом трёх видов медиа, два MP4, декодирование видео, аудио и SRT, правка одной сцены и переиспользование двух. |

## Подтверждённые проверки

- Аудит `51f33c3` на Windows. 17 из 17 исходных тестов прошли.
- QA на Windows. 41 тест обнаружен, 40 прошли. Проверка симлинка пропущена из-за разрешений контекста Windows. Покрытие 99,16% строк и 95,73% ветвей.
- Локальный Linux amd64 (Debian/Trixie в Docker, Xvfb, FFmpeg из imageio-ffmpeg 0.6.0). 41 из 41 теста прошёл, включая симлинк. Покрытие 98,92% строк и 96,58% ветвей.
- Ruff успешно проверил `efir`, `tests` и `scripts`. Форматы YAML GitHub, GitLab и Compose разобраны и проверены на типы команд.
- PR №1, исходный коммит до аудита. [GitHub Actions для Windows и Ubuntu](https://github.com/KoznovaAV/efir-studio/actions/runs/45184012248) завершился успешно. На первоначальном PR №2 автозапуск отсутствовал из-за фильтра базы `main`. Фильтр расширен на ветки цепочки.
- Изменения и проверки QA привязаны к [PR №3](https://github.com/KoznovaAV/efir-studio/pull/3). Там доступны статусы выполнения и архивы отчётов.

Ограничения верхнего уровня и условия запуска приведены в [чек-листе](REQUIREMENTS_CHECKLIST.md). Ручной прогон, нагрузка и Docker документируются отдельно.
